# 运维、备份与排障

本文覆盖生产环境最常见的问题：备份、上传失败、媒体 500、图片加载失败、地球仪卡顿、访问密码异常和数据库维护。

## 日常运维清单

建议定期检查：

- Docker 容器是否正常运行。
- `/app/data` 是否持续挂载。
- 磁盘空间是否充足。
- 数据库备份是否按时生成并发到邮箱。
- 队列中是否有大量失败任务。
- S3/COS 凭据是否过期或权限变化。
- 公开访问密码和预览数量是否符合预期。

## 数据库备份

入口：`后台 → 设置 → 系统设置 → 数据库备份`

支持配置：

- 是否启用自动备份。
- Cron 表达式或每日备份时间。
- 时区。
- 备份保留天数。
- SMTP 主机、端口、账号、密码。
- 发件人和收件人。
- 可选加密口令。

备份会使用 SQLite 在线备份能力生成数据库副本，再压缩发送到邮箱。备份文件也会保留在数据目录中，便于服务器本地恢复。

### 推荐策略

- 每天凌晨备份一次。
- 至少保留 7 到 30 天。
- 邮箱使用专用 SMTP 授权码，不要使用主账号密码。
- 重要站点同时做服务器磁盘快照或对象存储备份。

## 恢复数据库

恢复前先停止容器：

```bash
docker stop chronoframe
```

备份原数据库：

```bash
cp ./data/app.sqlite3 ./data/app.sqlite3.before-restore
```

解压备份文件并替换数据库，然后重新启动容器：

```bash
docker start chronoframe
```

如果备份启用了加密，需要先用对应口令解密。

## 上传失败

### `POST /api/photos: 500 Failed to prepare upload`

常见原因：

- 存储提供器配置错误。
- S3/COS Endpoint、Bucket 或 Region 不匹配。
- Access Key 没有写入权限。
- Docker 容器缺少可写数据目录。
- 数据库路径没有持久化或不可写。

排查顺序：

1. 后台检查当前启用的存储提供器。
2. 查看 Docker 日志。
3. 在云厂商控制台确认 Bucket 名称、区域、权限。
4. 确认容器内 `/app/data` 可写。
5. 上传一张很小的 JPEG 做最小复现。

### 腾讯云 COS 特别注意

腾讯云 COS 的 Bucket 名称通常带 AppID，例如：

```text
my-bucket-1250000000
```

Endpoint 通常是：

```text
https://cos.ap-guangzhou.myqcloud.com
```

Region 是：

```text
ap-guangzhou
```

`Force Path Style` 通常关闭。

## 图片或视频加载失败

如果列表中能看到记录，但详情页或缩略图加载失败，可能是：

- 对象存储中缺少对应文件。
- 存储 Key 不正确。
- 媒体代理鉴权未通过。
- 未输入访问密码且资源超出预览范围。
- S3/COS 读取权限不足。
- 缩略图任务失败。

排查：

1. 登录管理员账号再访问，排除访问密码限制。
2. 在后台照片列表查看该照片所属相簿、所有者、隐藏状态。
3. 查看系统日志中的 `/image`、`/thumb`、`/storage`、`/og-media` 错误。
4. 到对象存储控制台确认原图和缩略图对象存在。
5. 对失败任务执行重试。

## 直方图加载失败

直方图通常依赖可读取的原图或处理后的图像数据。失败原因多为：

- 原图代理返回 404/500。
- 图片格式处理失败。
- 对象存储读取超时。
- 访问权限限制导致服务端拿不到文件。

先修复原图访问，再重试直方图。

## MP4/MOV 处理失败

常见错误：

| 错误                                | 含义                   | 处理                                  |
| ----------------------------------- | ---------------------- | ------------------------------------- |
| `Unsupported MP4 video codec: hevc` | 旧版本只接受 H.264     | 更新到新镜像，新版本会转码 HEVC/H.265 |
| `ffprobe not found`                 | 环境缺少 FFprobe       | 使用官方 Docker 镜像或安装 FFmpeg     |
| `mkdtemp /tmp/chronoframe-video`    | 临时目录不可写或不存在 | 更新镜像，确保 `/tmp` 可写            |

视频转码比图片处理慢很多。大量视频上传时，建议分批上传。

## GPS 和位置不显示

如果照片显示无 GPS：

- 用系统照片 App 或 exiftool 确认原始文件真的有 GPS。
- 检查后台隐私设置是否开启“上传时擦除位置”。
- 查看队列任务是否完成。
- 如果使用 Live Photo，确认图片和 MOV 是否都成功上传。
- 检查位置提供器 Key 是否配置正确。

GPS 提取和逆地理编码是两件事。没有 GPS 坐标时，地图和地球仪不会显示这张照片；有 GPS 但逆地理编码失败时，仍然可以显示坐标点，只是地点名称可能为空。

## 地球仪卡顿

地球仪需要加载有 GPS 的照片点位和纹理。数据量变大后，性能瓶颈通常来自：

- 一次渲染的点位太多。
- 图片缩略图过大。
- 浏览器 WebGL 性能较弱。
- 页面初始化时同时请求太多媒体。

优化建议：

- 只在地球仪上使用必要字段，避免加载完整照片详情。
- 优先使用缩略图，不加载原图。
- 对点位做聚合或抽样。
- 避免在低端移动设备上一次展示全部点位。
- 使用 Chrome/Edge 等 WebGL 支持较好的浏览器测试。

## 访问密码异常

### 退出登录后首页没数据，也没跳访问页

这是预览模式的正常方向：不再要求一进入首页就输入密码。未验证访客应能看到配置数量内的公开内容。如果一张都没有，检查：

- 是否存在非隐藏公开照片。
- 匿名预览数量是否为 0。
- 照片是否都在隐藏相簿中。
- 媒体代理是否因为权限或存储错误返回失败。

### 输入密码后仍看不到更多内容

检查：

- 浏览器是否接受 Cookie。
- `NUXT_SESSION_PASSWORD` 是否在重启后变化。
- 访问密码是否刚被修改。
- 是否跨域或 HTTPS/HTTP 混用导致 Cookie 未携带。

## 容器日志

常用命令：

```bash
docker logs -f chronoframe
docker inspect chronoframe
docker exec -it chronoframe sh
```

查看数据目录：

```bash
docker exec -it chronoframe ls -lah /app/data
```

查看临时目录：

```bash
docker exec -it chronoframe ls -lah /tmp
```

## 升级前检查

升级前建议：

- 手动触发一次数据库备份。
- 确认当前镜像 tag 或 digest。
- 记录当前环境变量。
- 记录存储提供器配置。
- 确认磁盘空间充足。

升级后建议：

- 登录管理员后台。
- 上传一张小图测试。
- 打开首页、相簿、详情页、地球仪。
- 打开未登录匿名窗口测试访问密码和预览限制。
- 查看系统日志是否有新错误。
