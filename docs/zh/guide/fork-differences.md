# 与上游仓库的差异

本仓库 fork 自 [HoshinoSuzumi/chronoframe](https://github.com/HoshinoSuzumi/chronoframe)，在保留上游画廊体验的基础上，增加了多用户管理、更严格的权限隔离和可控的公开访问能力。

本文描述 [swzyt/chronoframe](https://github.com/swzyt/chronoframe) 当前维护的 fork 特性。上游仓库可能独立演进，升级或合并上游代码前应同时检查两个仓库的最新变化。

## 功能对比

| 功能           | 上游仓库                         | 当前 fork                                                                                                |
| -------------- | -------------------------------- | -------------------------------------------------------------------------------------------------------- |
| 用户模型       | 主要面向单管理员                 | 支持管理员和普通用户两种角色                                                                             |
| 用户创建       | 没有管理员创建本地用户的完整流程 | 管理员可创建用户、重置密码、启停账号、调整角色和删除用户                                                 |
| 注册           | 不提供公开注册                   | 不提供公开注册，账号统一由管理员创建                                                                     |
| 数据归属       | 内容按站点整体管理               | 照片、相簿和异步任务都有明确所有者                                                                       |
| 后台权限       | 主要面向管理员                   | 普通用户只可访问仪表盘、自己的照片和自己的相簿                                                           |
| 跨用户操作     | 单用户模型下不涉及               | 普通用户只能查询和操作自己的数据，管理员可管理全部数据                                                   |
| 公开画廊       | 直接展示公开内容                 | 聚合所有用户的非隐藏公开内容                                                                             |
| 公开展示模式   | 首页画廊、相簿和地球仪           | 新增相片流光墙，展示当前可见的公开相片                                                                   |
| 访客访问保护   | 整站访问密码拦截                 | 访客可先预览指定数量的照片和相簿，再输入密码解锁全部公开内容                                             |
| 媒体保护       | 采用上游常规存储访问流程         | 原图、缩略图、Live Photo 和下载均经过应用鉴权                                                            |
| 低成本媒体浏览 | 详情页直接浏览原图               | 图片上传时生成 2560px 长边 WebP 展示图；详情页、全屏和邻近预加载默认使用展示图，原图仅用于下载等明确动作 |
| 视频媒体       | 主要面向图片和 Live Photo        | 支持 MP4 上传、处理、缩略图/元数据提取和浏览器可播放视频                                                 |
| 地图服务商     | 以 Mapbox 相关流程为主           | 新增高德地图展示和高德逆地理编码，便于中国大陆部署                                                       |
| 分享预览       | 常规页面预览行为                 | 为照片和视频新增经过鉴权代理的 Open Graph 预览图                                                         |
| 多语言         | 上游已有翻译                     | fork 新增界面同步支持简中、繁中（台湾/香港）、英文、日文和俄文                                           |

## 用户与角色

当前 fork 沿用 `isAdmin` 表示管理员角色，并为用户增加启用状态。

管理员可以：

- 创建本地用户。
- 重置用户密码。
- 启用或停用账号。
- 将普通用户提升为管理员。
- 将管理员降为普通用户。
- 删除普通用户。
- 查看和管理所有用户的照片与相簿。
- 访问用户管理、队列、日志、存储和系统设置。

普通用户可以：

- 使用邮箱和密码登录。
- 查看仪表盘。
- 上传和管理自己的照片。
- 创建和管理自己的相簿。
- 在后台照片及相簿列表中只查看自己的数据。

服务端每次授权都会从数据库读取用户当前角色和启用状态，因此角色调整及账号停用不要求用户重新登录即可生效。

### 管理员安全规则

- 管理员不能降低、停用或删除自己的账号。
- 系统中最后一个可用管理员不能被降低、停用或删除。
- 删除管理员前必须先将其降为普通用户。
- 删除普通用户时，其照片、相簿和未完成任务会转移给执行删除操作的管理员。

## 数据归属与权限隔离

照片、相簿和异步队列任务均包含 `ownerUserId`。

- 数据迁移时，历史内容归属到最早创建的管理员。
- 新文件采用 `users/<userId>/...` 形式的用户隔离存储路径。
- 普通用户访问他人资源时返回 `404`，降低资源存在性泄露。
- 普通用户只能把自己的照片加入自己的相簿。
- 上传任务和后台处理结果会保留上传者的归属关系。
- 隐藏相簿仅所有者和管理员可见。

公开画廊仍会聚合所有用户的非隐藏公开内容。数据隔离限制的是后台管理操作，不影响用户主动发布到公开画廊的内容。

照片和相簿接口会在合适场景返回所有者信息，便于管理员和浏览者了解内容由谁上传或拥有。后台照片与相簿列表会展示这些信息，同时仍遵守普通用户只能查看和管理自己数据的隔离规则。

## 访客预览与访问密码

启用访问保护后，匿名访客进入站点时不会立即被要求输入密码，而是可以先预览：

- 默认最新 10 张公开照片。
- 默认最新 1 个公开相簿。

管理员可在「后台 → 基础设置 → 站点访问保护」中分别配置两个数量。

存在更多公开内容时，首页、相簿页和地球仪会显示解锁入口。访客输入正确密码后：

- 后端签发带签名的 HttpOnly、SameSite=Lax Cookie。
- 访问凭证有效期为 30 天。
- 页面、公开 API、原图、缩略图、Live Photo 和下载接口可返回全部授权公开内容。
- 已登录用户不需要输入访客访问密码。

Cookie 中包含访问密码版本。修改密码或调整保护配置并更新版本后，旧的访问凭证会立即失效。

同一来源在 15 分钟内最多允许 5 次失败尝试，超限后返回 `429`。

## 媒体访问保护

当前 fork 通过 ChronoFrame 应用层鉴权返回媒体，不依赖客户端可见的底层存储直链。

未解锁的匿名访客只能获取预览范围内照片对应的媒体。直接请求预览范围之外的相簿、缩略图、原图或 Live Photo，不能绕过数量限制。

使用 S3 或 OpenList 时，底层存储桶或存储服务仍应保持私有。如果存储桶本身公开，应用层访问控制将无法阻止用户直接访问对象。

## 公开展示模式

当前 fork 新增一个公开展示路由：

- `/album-flow` 将当前可见的公开相片渲染为动态流光照片墙，不展示相簿卡片。

该页面与首页共用同一套访客预览权限。未解锁的匿名访客只能看到后台配置的预览相片数量；已登录用户或持有有效访问 Cookie 的访客可以看到完整授权范围内的公开内容。页面只保留返回首页入口；只有存在更多相片可解锁时才显示解锁入口。

## MP4 视频支持与分享预览

当前 fork 除图片和 Live Photo 外，还支持上传 MP4。视频处理流程会提取元数据和封面图，记录视频所有者，并通过与其他受保护媒体一致的应用层鉴权返回浏览器可播放媒体。

照片和视频的分享预览使用应用自身的 Open Graph 媒体路由，不直接暴露底层存储对象。这样可以让分享预览继续遵守媒体保护模型，避免向客户端泄露存储 key 或私有对象地址。

## 地图与位置服务商

除上游已有地图能力外，当前 fork 新增高德地图支持，适合 Mapbox 注册或使用不便的部署环境。管理员可以在后台设置和初始化流程中配置地图展示服务商与逆地理编码服务商。

高德地图需要配置浏览器端地图 key；高德逆地理编码需要有效的 Web 服务 key。位置展示仍依赖上传的图片或视频源文件中实际存在 GPS 元数据。

## 数据库与升级注意事项

当前 fork 包含新增并强制数据归属的数据库迁移。升级前应：

1. 完整备份 `data` 目录和外部存储配置。
2. 确认系统中至少存在一个已启用的管理员。
3. 启动新版本并等待自动迁移完成。
4. 检查历史照片和相簿是否归属到预期管理员。
5. 分别使用管理员、普通用户和匿名访客完成验证。

不要在没有兼容数据库备份的情况下直接降级到不了解这些迁移的上游版本。

## 同步上游代码

合并上游改动时不应直接盲合，尤其需要仔细检查以下范围：

- 登录、认证和会话处理。
- 照片、相簿、队列及设置 API。
- 数据库结构和迁移文件。
- 存储路径及公开媒体地址。
- 全局路由中间件。
- 地图和画廊的数据加载逻辑。
- 公开预览权限和受保护媒体路由。
- MP4 处理与 Open Graph 预览图生成。

合并上游代码后，至少执行：

```bash
pnpm lint
pnpm db:check
pnpm build
```

随后应在接近生产的环境中验证管理员、普通用户、匿名预览、密码解锁、媒体访问、相簿和地球仪流程。
