# 与上游仓库的差异

本仓库 fork 自 [HoshinoSuzumi/chronoframe](https://github.com/HoshinoSuzumi/chronoframe)。当前维护的 [swzyt/chronoframe](https://github.com/swzyt/chronoframe) 保留了上游自托管照片画廊体验，但整体方向已经扩展为多用户、权限隔离、媒体保护和低成本部署的版本。

本文用于说明当前 fork 与原仓库的主要差异。上游仓库会独立演进，因此这里描述的是当前 fork 的实际能力，而不是对上游未来状态的永久判断。

## 总览

相比上游，当前 fork 主要新增和强化了：

- 管理员/普通用户两级账号体系。
- 照片、相簿和异步任务的数据归属。
- 匿名访客预览数量限制，以及访问密码解锁完整公开内容。
- 应用层媒体鉴权，不直接依赖底层存储直链。
- MP4/MOV 视频上传与处理，包括 HEVC/H.265 转浏览器可播放 H.264 资源。
- 高德地图/高德逆地理编码，适合中国大陆部署。
- 上传时生成展示图，降低 COS/S3/CDN 大图访问成本。
- 针对大图库的公开查询、相簿列表、地球仪和后台照片管理性能优化。
- 定时 SQLite 数据库邮件备份。
- 自动发布 GHCR 多架构 Docker 镜像。

## 功能对比

| 功能         | 上游仓库                         | 当前 fork                                                                                |
| ------------ | -------------------------------- | ---------------------------------------------------------------------------------------- |
| 用户模型     | 主要面向单管理员画廊             | 支持本地多用户，分管理员和普通用户                                                       |

| 公开注册     | 不提供公开注册                   | 仍不提供公开注册，账号由管理员创建                                                       |

| 存储后端     | 支持本地/S3/OpenList             | 强化本地/S3/OpenList 行为，补充腾讯云 COS 兼容配置，支持 S3/本地流式读取和受保护媒体访问 |
| 视频         | 主要面向图片和 Live Photo        | 支持 MP4/MOV、元数据提取、封面生成、HEVC/H.265 转 H.264 播放资源                         |
| 所有者展示   | 不是核心信息                     | 照片和相簿在合适位置展示上传者/所有者信息                                                |
| 相簿归属     | 支持相簿照片关系编辑             | 后台照片列表展示全部所在相簿，支持单张和批量设置照片相簿                                 |
| 公开展示模式 | 首页、相簿、照片详情、地球仪     | 新增 `/album-flow` 动态相片流光墙                                                        |
| 图片详情查看 | 上游查看器能力                   | 增加自动播放、旋转、全屏、缩放/拖拽优化和视频详情展示                                    |
| 地图         | 以 Mapbox 流程为主               | 增加 MapLibre/高德地图展示，以及高德/Mapbox/Nominatim 逆地理编码选择                     |

## 用户与权限变化

当前 fork 沿用 `isAdmin` 作为管理员角色标记，并增加账号启用状态。用户管理仅管理员可访问。

管理员可以：

- 创建本地用户。
- 重置密码。
- 启用或停用账号。
- 将普通用户提升为管理员。
- 将管理员降为普通用户。
- 删除普通用户。
- 查看和管理所有用户的照片与相簿。
- 访问队列管理、系统日志、用户管理、存储设置和系统设置。

普通用户可以：

- 使用邮箱和密码登录。
- 查看仪表盘。
- 上传和管理自己的照片。
- 创建和管理自己的相簿。
- 在后台照片和相簿列表中只看到自己的数据。

安全规则：

- 管理员不能降低、停用或删除自己的账号。
- 系统中最后一个已启用管理员不能被降低、停用或删除。
- 删除管理员前必须先将其降为普通用户。
- 删除普通用户时，其照片、相簿和未完成任务会转移给执行删除操作的管理员。
- 普通用户越权访问他人资源时返回 `404`，减少资源存在性泄露。

## 数据归属与隔离

当前 fork 为照片、相簿和异步处理任务增加了 `ownerUserId`。

- 历史内容在迁移时归属到最早创建的管理员。
- 新上传文件使用类似 `users/<userId>/...` 的用户隔离存储路径。
- 上传任务和处理结果会保留上传者归属。
- 普通用户只能把自己的照片加入自己的相簿。
- 管理员可以跨用户查看和操作。
- 公开页面仍聚合所有用户的非隐藏内容。
- API 会在合适场景返回所有者信息，后台列表和内容信息区会展示上传者/所有者。

## 访客预览与访问密码

启用公开访问保护后，匿名访客不会一进站就被拦截，而是可以预览：

- 可配置数量的公开照片，默认 10 张。
- 可配置数量的公开相簿，默认 1 个。

如果站点存在更多公开内容，公开页面会显示解锁入口。输入正确访问密码后：

- 后端校验密码并签发带签名的 HttpOnly Cookie。
- Cookie 有效期为 30 天。
- Cookie 携带访问密码版本，修改密码或相关配置后可让旧凭证失效。
- 已登录用户不需要输入访客访问密码。
- 同一来源 15 分钟内最多允许 5 次失败尝试，超限返回 `429`。

预览限制会覆盖公开页面、公开照片/相簿 API、地球仪 marker、相簿详情、缩略图、原图、Live Photo 和下载接口。

## 媒体、视频与成本优化

当前 fork 将媒体访问统一收敛到 ChronoFrame 应用层，而不是依赖底层对象存储直链。这样本地存储、S3 兼容存储、腾讯云 COS 和 OpenList 可以共用一套权限模型。

主要媒体变化：

- 上传处理时生成缩略图和展示图。
- 图片详情、全屏查看和邻近预加载默认使用展示图。
- 原图继续保留，但更严格保护，主要用于明确下载或原图相关流程。
- S3 和本地存储提供流式读取和 Range 流式读取能力，降低大媒体内存压力。
- 媒体响应支持缓存、条件请求和 Range 请求。
- 分享预览使用应用自己的 Open Graph 媒体路由，不暴露底层存储 key。
- 直方图不再给缩略图请求追加时间戳，允许浏览器/CDN 缓存命中。

视频变化：

- 支持 MP4 上传。
- 支持 MOV/Live Photo 相关资源。
- HEVC/H.265 输入可生成浏览器友好的 H.264 播放资源。
- 记录视频元数据、时长、编码、封面缩略图和播放 key。
- 视频播放与照片一样经过受保护媒体层。

## 公开展示与查看器变化

当前 fork 增加和调整了多个公开访问体验：

- `/album-flow` 将当前可见的公开相片渲染为动态流光墙。
- 未解锁匿名访客只能看到后台配置的预览数量。
- 相簿详情页在未解锁时也只展示允许数量的照片。
- 照片详情支持自动播放式切换、全屏、旋转、更稳定的缩放/拖拽以及视频展示。
- 相簿和照片信息在合适位置展示所有者，便于理解内容来源。

独立幻灯片页面已移除，自动播放能力转移到照片详情页中。

## 地图与位置能力

除上游地图能力外，当前 fork 增加了更适合中国大陆部署的地图和位置能力：

- 高德地图展示服务商。
- 高德逆地理编码服务商。
- 仍保留 Mapbox 和 Nominatim 逆地理编码选择。
- 地图服务商配置出现在初始化流程和后台设置中。
- 位置展示仍依赖上传源文件真实存在 GPS 元数据。

地球仪页面针对大图库进行了优化：

- 使用 `/api/photos/map`，不再加载完整公开照片 payload。
- 地图 API 只返回地球仪所需 marker 字段。
- API 支持视野 bounds。
- 低缩放级别可由服务端网格聚合。
- 前端聚合仍作为补充和兜底。

## 性能优化

当前 fork 包含多项面向大图库和对象存储成本的优化。

### 查询与 API 优化

- 公开照片查询使用 SQL `NOT EXISTS` 排除隐藏相簿照片，不再把隐藏照片 ID 全量读进 Node.js 内存。
- 公开相簿预览数量下推到 SQL，不再先查全量再 `slice`。
- 公开访问摘要中的照片/相簿总数使用 `COUNT(*)`。
- 相簿列表 API 批量查询相簿照片关系和预览照片，避免 N+1 查询。
- 后台照片管理支持服务端分页、搜索、媒体类型筛选和只返回分页元信息的轻量请求。
- 为存储 key、所有者、时间排序、相簿可见性、相簿照片排序和 GPS 坐标补充数据库索引。

### 地球仪优化

- 地球仪数据加载改为轻量 marker。
- 地图加载后按当前视野请求数据，减少 marker payload。
- 低缩放服务端聚合，避免浏览器渲染和聚合过多点位。
- 传给地球仪的 EXIF 字段经过裁剪，只保留注解所需字段。

### 媒体与成本优化

- 展示图减少 COS/S3/CDN 重复传输大原图的费用。
- 原图媒体读取优先使用流式/Range 能力。
- 缩略图直方图请求可以命中缓存。
- 受保护媒体路由避免客户端直接拿到底层私有存储地址。

### Docker/CI 优化

- GHCR 镜像在 push、tag 和手动触发时自动发布。
- 镜像同时构建 `linux/amd64` 和 `linux/arm64`。
- 发布流程已调整为适合 fork 的公开镜像交付。

## 备份与运维

当前 fork 新增定时数据库备份：

- 在后台系统设置中配置。
- 创建安全 SQLite 备份。
- 压缩数据库。
- 可选加密备份附件。
- 通过 SMTP 邮件发送。
- 按配置保留天数清理本地旧备份。

最近的备份加固将加密备份改为流式格式（`CFDBENC2`），大数据库备份时不再需要把整个压缩文件读入内存。

生产环境如果使用本地媒体存储，仍建议额外备份完整 `/app/data` 目录。

## Docker 部署差异

当前 fork 发布公开镜像：

```text
ghcr.io/swzyt/chronoframe:latest
```

镜像内包含 fork 运行所需能力，包括视频和元数据处理使用的 FFmpeg/FFprobe 与 ExifTool 路径。

推荐 Docker 配置：

- 保持 `NUXT_SESSION_PASSWORD` 在重启和升级后稳定不变。
- 使用 `DATABASE_URL=/app/data/app.sqlite3`。
- 持久化挂载 `/app/data`。
- 保证 `/tmp` 可写，用于媒体处理。
- 如果依赖 ChronoFrame 应用层鉴权，外部对象存储桶应保持私有。

## 数据库与升级注意事项

当前 fork 包含上游不了解的数据库迁移，包括所有权字段、媒体字段、视频字段、展示图、访问密码设置、备份设置和性能索引。

升级前应：

1. 备份 `data`、`.env`、Docker Compose 文件和外部存储配置。
2. 确认至少存在一个已启用管理员。
3. 启动新镜像并等待数据库迁移完成。
4. 检查历史照片和相簿是否归属到预期管理员。
5. 验证管理员、普通用户、匿名预览、密码解锁、上传、媒体、相簿和地球仪流程。

不要在没有兼容备份的情况下直接降级到上游或更旧 fork 版本。

## 同步上游代码

合并上游代码时需要重点审查：

- 登录、会话、中间件和路由守卫。
- 照片、相簿、队列、存储、设置或地图 API。
- 数据库结构和迁移。
- 媒体 URL 生成或存储对象路径。
- 公开画廊数据加载。
- 查看器行为。
- 视频、Live Photo、EXIF、GPS 或逆地理编码处理流程。
- i18n 多语言文件。
- Docker 镜像或 CI 工作流。

合并上游改动后，至少执行：

```bash
pnpm lint
pnpm db:check
pnpm docs:build
pnpm build
```

随后应在接近生产的容器环境中验证：

- 管理员登录和完整后台权限。
- 普通用户登录和数据归属隔离。
- 匿名访客解锁前预览。
- 密码解锁，以及修改密码后旧 Cookie 失效。
- 图片/视频上传与队列处理。
- S3/COS/OpenList/本地媒体加载。
- 相簿列表和详情权限。
- 地球仪和地图服务商行为。
