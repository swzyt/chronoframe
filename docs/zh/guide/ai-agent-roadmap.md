# AI / Agent 功能路线

这份文档记录 ChronoFrame 后续可以探索的 AI 与 Agent 能力方向。它不是当前已完成能力说明，而是面向未来版本的产品路线草案。

ChronoFrame 已经具备照片上传、相簿管理、多用户权限、公开访问控制、地图、媒体保护与低成本展示图等基础能力。下一阶段如果要紧跟 AI / Agent 产品趋势，重点不应只是给照片“打标签”或“生成描述”，而是把 ChronoFrame 扩展成一个能理解、整理、策展和引导浏览照片库的照片记忆代理。

## 产品定位

建议方向：

> ChronoFrame 不只是一个自部署相册，而是一个 AI-native 的个人记忆与影像策展系统。

核心关键词：

- 照片记忆代理
- 自动整理
- 语义搜索
- AI 策展
- 访客导览
- 隐私审查
- Agent 工作流
- MCP / Agent API

## 推荐优先级

### P0：AI 照片管家 Agent

这是最有辨识度的方向。目标不是让 AI 只回答问题，而是让它能帮助管理员真正管理照片库。

管理员可以用自然语言提出任务：

- 把这次日本旅行的照片整理成 3 个相簿。
- 找出最近上传照片里最适合公开展示的 30 张。
- 把重复、模糊、曝光失败的照片标出来。
- 帮我给这个相簿写标题和简介。
- 把最近上传的照片按城市和日期整理一下。
- 找出没有相簿归属的高质量照片，并推荐归属相簿。

建议交互流程：

1. 管理员输入目标。
2. Agent 分析照片、EXIF、地点、时间、相簿关系和公开状态。
3. Agent 给出执行计划。
4. 管理员确认。
5. 系统执行变更。
6. Agent 输出变更摘要，并支持撤销或二次调整。

需要注意：

- Agent 不应默认直接修改大量数据。
- 所有批量操作应先生成计划，再由管理员确认。
- 高风险操作，例如隐藏、删除、移动大量照片，需要明确确认。
- 普通用户只能让 Agent 操作自己的数据。
- 管理员 Agent 可以跨用户管理，但需要保留审计日志。

### P0：自然语言照片搜索

让用户可以用自然语言查找照片，而不是只能靠日期、地点、相簿筛选。

示例查询：

- 去年冬天在海边拍的人像。
- 有猫、窗户、夕阳的照片。
- iPhone 拍的 Live Photo。
- 适合做首页封面的横图。
- 没有 GPS 但看起来像在室内餐厅的照片。
- 东京夜景里构图比较好的照片。

建议采用混合检索：

- 图片向量 embedding。
- AI 生成的照片描述。
- EXIF 条件过滤。
- 地点与时间过滤。
- 相簿、隐藏状态、所有者权限过滤。

权限规则：

- 匿名用户只能搜索公开且当前有权访问的内容。
- 未输入访问密码时，只能命中预览额度内允许访问的照片。
- 普通用户只能搜索自己的后台数据。
- 管理员可以搜索全部后台数据。

### P1：AI 自动相簿生成

上传一批照片后，系统可以自动生成相簿草稿。

生成维度：

- 时间线。
- 地点。
- 城市。
- 人物或宠物。
- 场景。
- 主题。
- 视觉风格。
- 故事连贯性。

示例输出：

- 东京街头
- 夜色与霓虹
- 餐桌记忆
- 人物精选
- 胶片感瞬间

建议设计：

- 自动相簿先作为草稿，不直接公开。
- 支持管理员预览、编辑、合并、删除草稿。
- 支持“重新生成”或“按我的描述重新整理”。
- 支持把无相簿归属照片作为优先处理对象。

### P1：AI 相片评分与精选

为照片生成多个可解释分数，用于筛选和策展。

可评分维度：

- 清晰度。
- 构图。
- 曝光。
- 情绪感。
- 美学评分。
- 是否适合公开。
- 是否适合做封面。
- 是否疑似重复。
- 是否包含隐私风险。

后台可以提供筛选：

- 只看 8 分以上照片。
- 推荐首页封面。
- 找出某个相簿里最好的 20 张。
- 找出低质量或重复照片。
- 批量隐藏不适合公开的照片。

建议不要把 AI 分数包装成绝对判断，而应作为辅助管理信息。

### P1：AI 相片故事生成

照片站公开展示时，文字叙事会显著提升质感。

可生成内容：

- 相簿标题。
- 相簿简介。
- 单张照片描述。
- 旅行游记。
- 摄影展风格导语。
- 小红书 / Instagram 风格文案。
- 多语言描述。

建议能力：

- 支持按风格生成，例如纪实、胶片、旅行、摄影展、生活碎片。
- 支持管理员手动编辑 AI 输出。
- 支持中英文多语言生成。
- 支持为公开相簿生成 SEO 描述和 Open Graph 文案。

### P1：AI 访客导览员

公开站点可以增加一个“相册导览 Agent”，让访客不只是翻列表，而是被引导浏览。

访客可以问：

- 这个站点有哪些旅行照片？
- 带我看看城市夜景。
- 推荐几张适合当壁纸的照片。
- 这个相簿讲的是什么？
- 有没有在海边拍的照片？

导览 Agent 可以：

- 基于公开可见内容回答。
- 推荐照片和相簿。
- 带访客跳转到对应页面。
- 尊重访问密码与预览数量限制。
- 不泄露隐藏相簿、私有照片和后台信息。

这项能力会让公开站点更像一个会说话的影像空间，而不是传统图片列表。

### P2：AI 隐私审查

如果站点公开，隐私审查会很重要。

可检测内容：

- 人脸。
- 车牌。
- 证件。
- 屏幕截图中的敏感信息。
- 儿童照片。
- 精确 GPS 位置风险。
- 不适合公开的内容。

建议操作：

- 建议隐藏。
- 建议移除 GPS。
- 建议打码。
- 建议仅登录用户可见。
- 建议不要作为首页或公开相簿封面。

隐私审查结果应该可解释，并由管理员最终决定。

### P2：Agent 工作流编排

后台可以增加一个 Agent Workflow 页面，把上传后的处理链路可视化。

示例工作流：

1. 提取 EXIF。
2. 生成缩略图和展示图。
3. 生成视觉描述。
4. 生成 embedding。
5. 检测重复照片。
6. 判断是否适合公开。
7. 推荐相簿。
8. 生成相簿故事。
9. 发送处理日报。

建议支持：

- 每个步骤可开启或关闭。
- 每个步骤有成本估算。
- 失败可重试。
- 执行结果可追踪。
- 管理员可以手动触发某个工作流。

### P2：MCP / Agent API

为了贴合 Agent-native 方向，可以让 ChronoFrame 暴露 MCP Server 或 Agent API，使外部 AI 工具能够安全操作照片库。

可暴露能力：

- 搜索照片。
- 查询照片元数据。
- 创建相簿。
- 修改相簿内容。
- 给照片打标签。
- 生成分享链接。
- 上传照片。
- 查询存储与流量统计。

安全原则：

- MCP 工具必须复用现有用户权限。
- 管理员能力和普通用户能力要分开。
- 高风险写操作需要确认。
- 所有 Agent 操作写入审计日志。

### P3：AI 自动修图与衍生资产

这个方向更重，也更容易产生较高成本，可以放在后面。

可选能力：

- 一键增强。
- 去噪。
- 超分。
- 黑白版本。
- 胶片风格。
- 自动裁剪为社交媒体比例。
- 为相簿生成海报封面。
- 为照片生成低成本分享预览图。

建议只作为可选插件或按需任务，不作为默认上传链路。

## 技术设计草案

### 数据结构

可考虑新增以下实体：

- `photo_ai_metadata`
  - 照片描述。
  - 标签。
  - embedding 状态。
  - 质量评分。
  - 隐私风险。
  - 模型版本。

- `ai_jobs`
  - 任务类型。
  - 任务状态。
  - 触发用户。
  - 目标资源。
  - 输入参数。
  - 执行结果。
  - 错误信息。

- `agent_plans`
  - 用户输入。
  - Agent 生成的计划。
  - 待执行操作列表。
  - 确认状态。
  - 执行状态。

- `photo_embeddings`
  - 照片 ID。
  - embedding 模型。
  - 向量数据或外部向量库引用。
  - 更新时间。

### 后台页面

建议新增：

- AI 管家。
- AI 任务队列。
- AI 元数据状态。
- AI 搜索。
- 自动相簿草稿。
- 隐私审查。
- Agent 工作流。

### 权限边界

AI 能力必须复用现有权限模型：

- 匿名用户只能访问公开且已授权的内容。
- 未输入访问密码时，AI 导览也只能看到预览额度内内容。
- 普通用户只能操作自己的照片和相簿。
- 管理员可以操作全部数据。
- AI 写操作需要记录执行用户和来源。

### 成本控制

AI 能力需要内置成本意识：

- 上传后默认不对原图做高成本模型处理。
- 可以先生成低成本缩略图描述，再按需处理大图。
- 批量任务需要显示预计处理数量。
- 支持每日 / 每月 AI 调用额度。
- 支持仅管理员触发高成本任务。
- AI 元数据应缓存，模型版本变化时再增量刷新。

## 分阶段实现建议

### 阶段一：AI 元数据基础层

目标：

- 为照片生成描述、标签、基础质量评分。
- 支持后台查看 AI 元数据。
- 支持手动重新分析。

价值：

- 为自然语言搜索、自动相簿和 Agent 管理打基础。

### 阶段二：自然语言搜索

目标：

- 支持语义搜索照片。
- 支持结合时间、地点、相机、相簿、公开状态过滤。
- 严格接入现有权限。

价值：

- 用户可立即感知 AI 能力。

### 阶段三：AI 照片管家 Agent

目标：

- 支持自然语言整理照片。
- 支持生成计划、确认执行、审计记录。
- 支持创建相簿、移动照片、推荐隐藏、推荐封面。

价值：

- 形成 ChronoFrame 的核心差异化。

### 阶段四：访客导览 Agent

目标：

- 公开站点支持自然语言导览。
- 根据公开权限推荐照片和相簿。
- 支持跳转和浏览引导。

价值：

- 让公开站点从静态画廊变成互动式影像空间。

### 阶段五：MCP / Agent API

目标：

- 让外部 AI 工具可以安全操作 ChronoFrame。
- 提供搜索、创建相簿、整理照片等工具能力。

价值：

- 让项目具备 Agent-native 生态能力。

## 不建议优先做的方向

短期不建议优先做：

- 大规模 AI 修图。
- 复杂人脸识别。
- 社交平台。
- 公开评论系统。
- 自动发布到第三方平台。

原因：

- 成本高。
- 隐私风险高。
- 容易偏离 ChronoFrame 的核心定位。
- 需要大量额外审核与安全设计。

## 推荐下一步

如果要正式开始开发，建议从最小可用闭环开始：

1. 新增 AI 元数据表。
2. 上传后异步生成照片描述与标签。
3. 后台照片详情展示 AI 描述。
4. 增加自然语言搜索接口。
5. 搜索结果严格复用当前权限与访问密码逻辑。

这个闭环小、风险可控，又能为后续 AI 管家 Agent 打基础。
